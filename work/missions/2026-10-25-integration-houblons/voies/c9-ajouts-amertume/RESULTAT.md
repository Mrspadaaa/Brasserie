## Comment les valeurs sont croisées (brasseur : « panel croisé de plusieurs sources »)
- Le croisement existe déjà dans `fusion.mjs` (enveloppe `e`, raisons `h-`/`s-`, consensus à 3 sources). **Il n'est pas importable** (script, pas module) : je réemploie son résultat (`complements.json`, les valeurs `v` avec leur raison), je n'en recopie pas la règle. Ce qui est neuf : le **calibrage** des sources qui n'écrivent pas leurs unités.
- Calibrage mesuré (`node scripts/collecte-hop/c9-ajouts.mjs --calibrage`) : HopDatabase recoupe les autres sources à 97 % (α, n=184), 99 % (β), 100 % (cohumulone), 99 % (huile) ; hops-json 99 % (α), 100 % (β), 99 % (cohumulone, huile). Seuil 90 %, 30 valeurs au moins : ces champs sont admis (marque `u`). Humulène (3 %) et polyphénols (89 %) restent refusés. L'écart avec la fusion : HopDatabase et hops-json y sont des copies sans voix propre ; ici ils servent quand aucune autre fiche n'a la valeur.
- Chaque ajout porte `croise.<champ> = { n, ecart, voix: [[source, min, max, marque]…] }` (marques : `f` fiche valide, `u` unité non écrite mais source calibrée, `r` recettes, `s` signalée suspecte, `x` écartée). `n` = nombre de sources, `ecart` = écart des milieux (points). Une valeur qui s'écarte reste dans `voix` avec sa marque `s`, ni gardée seule ni effacée.
- Une plage de **recettes** (Beer Analytics : du 10e au 90e centile de l'histogramme du site ; Brewer's Friend : moyenne pondérée par les recettes) ne sert de plage que si aucun producteur ne donne la valeur ; le champ est alors dans `declare` (52 ajouts pour l'α), `purpose` et `origin` pris de Beer Analytics aussi. « 1 source » = `croise.<champ>.n === 1` (48 α sur les 76 n'ont qu'une voix). Un houblon à une seule source reste montré.
- `peuDeDonnees` (tri à égalité, D175) compte maintenant aussi les voix de recettes ; sens inchangé.

Recommandation : garder, mais l'écran ne doit pas l'afficher comme une fiche.
